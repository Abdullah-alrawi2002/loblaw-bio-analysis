# Loblaw Bio immune cell analysis

A complete, reproducible solution for `cell-count.csv`: a relational SQLite database, a direct Python loader, frequency tables, subject-aware statistics, baseline queries, and an interactive dashboard.

**Main finding:** none of the five cell populations differs significantly between response groups after Holm correction in the primary independent-subject analysis. CD4 T cells have U = 59,855, raw p = 0.012422, adjusted p = 0.062111. See [REPORT.md](REPORT.md) for the full results and limitations.

## Dashboard

**Live dashboard:** [https://abdullah-alrawi2002.github.io/loblaw-bio-analysis/](https://abdullah-alrawi2002.github.io/loblaw-bio-analysis/)

The hosted page is rebuilt by GitHub Actions on every push to `main` by running `make setup`, `make pipeline`, and `make test`, then publishing `dist/`. The same page is served locally by `make dashboard`, and `dist/index.html` can also be opened directly in a browser with no server.

## Run it (GitHub Codespaces)

1. Open the repository on GitHub, then **Code → Codespaces → Create codespace on main**. The included `.devcontainer` uses Python 3.12 and runs `make setup` automatically.
2. In the Codespace terminal, from the repository root:

```bash
make setup       # install pinned dependencies from requirements.txt
make pipeline    # load CSV -> SQLite, run Parts 2-4, write outputs/ and REPORT.md, build dist/index.html
make dashboard   # serve the dashboard on port 8501
```

3. Codespaces forwards port **8501** and offers to open it in the browser (or use the **Ports** tab). Stop the server with Ctrl+C.

Optional: `make test` runs the Python tests and, when Node is available, the dashboard check. `make clean` deletes the generated database.

| Target | What it does |
| --- | --- |
| `make setup` | `python3 -m pip install -r requirements.txt` (pinned pandas, NumPy, SciPy, Matplotlib) |
| `make pipeline` | `load_data.py` builds `immune_cells.db` from `cell-count.csv`; `analysis.py` runs Parts 2-4 against that database and writes `outputs/` and `REPORT.md`; `build_dashboard.py` writes `dist/index.html` |
| `make dashboard` | Checks that `immune_cells.db` exists (otherwise asks you to run `make pipeline`), refreshes the dashboard data from that database if it is out of date, and serves it at `http://localhost:8501` |

`PYTHON` and `PORT` can be overridden, for example `make dashboard PORT=8600`.

### Without Make

Use **Python 3.11+** (tested with 3.12):

```bash
python -m pip install -r requirements.txt
python load_data.py
python analysis.py
python build_dashboard.py
python dashboard.py
```

`load_data.py` uses only the Python standard library. It accepts no required arguments and creates `immune_cells.db` in the repository root. All paths resolve from the script directory, so the loader also works when invoked from a different working directory. Subsequent runs validate and atomically rebuild the database instead of appending rows. The database is a generated output and is not committed.

## Relational design

| Relation | Key | Relationship / fields |
| --- | --- | --- |
| projects | project | One project has many enrollments |
| subjects | subject | Sex; one subject can join multiple projects |
| enrollments | project, subject | References projects and subjects; condition, enrollment age, treatment, response |
| samples | sample | References a project/subject enrollment; specimen type and treatment-relative day |
| populations | population | Five population names, labels, display order |
| cell_counts | sample, population | Non-negative integer count; references samples and populations |
| load_metadata | key | Source filename, SHA-256, row count, schema version |

No totals or percentages are duplicated in storage. `sample_frequencies` derives them from counts, and `sample_metadata` joins enrollment/subject/sample attributes. A population row can be added without changing the measurement-table shape; the current loader deliberately requires the task's five known population columns. Indexes support cohort and baseline filters.

The source has globally unique subject IDs and consistent sex per subject. Trial attributes are constant within project/subject enrollments. Validation enforces those assumptions rather than silently selecting conflicting values. Blank response labels are preserved as NULL and excluded from response comparisons; any response other than `yes`, `no`, or blank is rejected with a validation error. `analysis.py` rebuilds the database automatically when the CSV's SHA-256 no longer matches the one stored in `load_metadata`. Zero-total samples, if introduced, have NULL percentages and are excluded from inferential analysis; the supplied file has none.

## Statistical choices

The requested cohort contains **1,968 samples from 656 subjects**, each measured at days 0, 7, and 14. The primary analysis computes each subject's mean sample percentage for each population and applies two-sided Mann–Whitney U tests across the independent responder and non-responder groups. Treating all 1,968 visits as independent would inflate the effective sample size.

Holm adjustment covers the five populations and controls family-wise error under arbitrary dependence, suitable for compositional proportions. The report provides responder-oriented U, raw p, adjusted p, medians, and rank-biserial effects. The baseline comparison is an exploratory sensitivity analysis. Day 7 and day 14 views each have their own five-test Holm correction; the collection of all selectable views is not jointly corrected. The all-sample view is descriptive and has no inferential p-values.

The estimates are unadjusted associations, not causal drug effects or validated prediction results. Primary averages use post-treatment data; baseline-only modeling and held-out validation would be necessary to make a prediction claim. `quintazide` is absent from the file and is not part of the specified miraclib cohort.

## Dashboard use

- **Treatment response:** select subject averages, baseline, day 7, day 14, or all samples. Inspect five boxplots, hover for values, and download the corresponding Python statistics.
- **Data overview:** filter by project, condition, treatment, specimen type, response, and visit; search a sample ID, browse the five-column summary, and download every matching row. Filters apply only to this overview.
- **Baseline cohort:** inspect the fixed day-0 melanoma/miraclib/PBMC subset, counts by project, distinct subjects by response and sex, missing response/sex counts, and download both the summary tables and all eligible samples.

The overview CSV always has exactly `sample,total_count,population,count,percentage`. Display rounding does not affect tests or exports. All counts, U statistics, and p-values come from this dataset; no mock data or external clinical data are used. File exports escape text fields that could be interpreted as spreadsheet formulas.

## Verification

```bash
make test
# or: python -m unittest discover -s tests -v && node tests/check_dashboard.cjs
```

The Node check is optional for users who only run Python. Nine Python tests verify source-to-database preservation, exact summary columns, denominator arithmetic, NULL responses, repeat-visit aggregation, Holm correction (including the p = α boundary), baseline totals and missing-value counts, reruns, rebuilds after CSV changes, invalid-input rollback, and zero denominators. The JavaScript check independently matches all displayed group medians to Python, exercises every comparison mode, tests filter/reset/search and empty states, and invokes CSV actions in a minimal DOM harness.

Static plot images and all three dashboard views were visually inspected in a browser. Download behavior and keyboard navigation were not tested end to end. The optional WebMCP tool is feature-detected; unsupported browsers use the same ordinary controls.
